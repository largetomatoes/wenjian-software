# 问间 3.1415（347）本机修补

2026-11-03。依据 346 复查报告修复五项问题。本次用户已选择正常保存退出并替换主应用；桌面演示版保持原样。此次未请求或执行 GitHub 推送、公开发布、Windows／Android 安装包或在线 Web App 部署。

## 已修改

1. 草稿每次写入带递增序号；退出前先等待已有队列，重试只使用仍然最新的失败稿。旧失败不能重建过期重试状态，旧成功也不能清除新错误。
2. 旧提交得到明确 409 时，先把原始请求写入 `record-conflict:<mutationId>` 恢复记录，再解除活跃意图的阻塞；归档写入失败时保留原意图。网络不确定或 503 不被当作已结束的冲突。
3. 新空稿与已保存笔记分开处理；已有笔记清空正文可以保存，原文仍成为修改历史，不永久删除。
4. 客户端按需请求 `responseProtocol:1`，服务仅返回已核验历史前缀之后的新增历史。客户端复用不可变旧数组；若确认引用无法匹配，则以同一 mutationId 请求原始完整回执，避免读取并误用更晚的新记录。旧客户端不带此标志时仍收到完整回执，完整备份／同步数据结构不变。
5. 更新完成并收到带 nonce/build 的成功状态后，登记明确的安装产物清单。仅整理清单内身份与文件指纹均匹配的成功更新产物，保留最近 1 个回退程序、1 个下载 ZIP 和 3 份更新保护点。损坏清单、未知旧副本、旧格式安装任务、失败或回滚任务、软链接、发现笔记／原书、内容被改动的副本均跳过。正常启动可补登记“安装已成功、整理尚未完成”的任务。手动安装器生成的未知目录不通过全盘扫描删除。
