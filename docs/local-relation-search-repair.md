# 联系草稿与共同笔记检索修补

2026-11-03，在本机 3.1415（347）源码基础上修补。未修改版本清单，未替换主应用或桌面演示版，未公开发布；交付 ZIP 是本轮经过验证的候选包。

## 修正行为

### 未提交的联系说明

- “梳理联系”中的摘录选择、关系名称、解释和正在修改的关系 ID，会暂存到本机恢复草稿。
- 立即切换笔记时，先等草稿落盘；正常退出阅读、退出应用和重启后可以继续写。
- 每篇笔记、每个阅读窗格单独保存，避免对照阅读的两个编辑区互相覆盖；同一窗格可以从不同来源书籍继续同一篇笔记。
- 暂存不是提交。点击“保存这条联系”后，先保住含完整关系说明的笔记草稿，再清理暂存状态；正式笔记继续走原来的保存及修改历史机制。
- 明确取消会清理本次联系草稿，不更改原先保存的关系。草稿读取或写入失败会提示，支持重试；读取失败时不覆盖原草稿。
- 恢复后若有引用已变动或移除，解释仍保留；界面要求核对选择，不静默丢弃失效引用，也不自动提交。

新的暂存内容使用既有草稿存储，完整备份仍会包含它。不把尚未提交的关系当作正式笔记同步到其他设备。

### 找回共同笔记

- 为每篇笔记的有效引用建立所有来源书籍和章节的索引，不只归入第一本书、第一处章节。
- 书库文件夹与 Zotero 分类的搜索可以找到涉及其书籍的共同笔记；点击仍打开同一篇原笔记，不复制内容。
- 同一笔记在同一书籍、同一章节内去重，保留各本书、各章节下各自的入口。
- 支持笔记板、旧段落式笔记；标题、正文、主题标签、用户写下的联系说明、后来想到的内容及回答纳入相关检索。
- 显示名称沿用用户在软件内设置的书名；来源章节不会错误借用另一本文献的章节。解除引用后，不用来源池中的旧残留制造当前关联。

- `lib/use-reading-relation-draft.ts`：联系编辑状态的读取、暂存、刷新和错误反馈。
- `components/reading-paper-editor.tsx`：恢复联系编辑、提交与取消顺序、失效引用提示。
- `components/book-note-editor.tsx`：切换前等待关系草稿，正式关系提交前保护完整笔记草稿。
- `lib/library-note-search.ts`：多书、多章节索引及结果去重。
- `components/global-search.tsx`：补齐主题、旧段落标题及笔记后续思考的检索。
- `tests/test-library-note-search.mjs`：多来源、章节、主题、说明、回答、重复引用及归属回归。
- `tests/test-relation-draft-ui.cjs`：独立 Mac 候选包的端到端交互回归，必须显式指定候选应用和输出目录。
