# 问间 3.14（330）统一发布计划与执行记录

日期：2026-10-19。Windows 3.14（321.2）已获使用者认可；以这套已验证代码为共同基础，优先解决关联问题难找、多路交叉不清楚，再完成 EPUB 与各平台适配后统一发布。显示版本及内部构建均使用 330，高于现有已知构建，保留原更新签名及应用身份。

## 已确认的设计约束

- 问题树保留原父子关系、编号与全部展开的全貌。关联选择中的折叠仅作用于选择器，不折叠主图。
- 普通问题先显示主问题，按需逐级展开；搜索同时查编号、标题与路径，已选项在折叠后仍可见、可取消。
- X 编号表示独立交叉思考，具有多个并列来源；不默认归为第一个来源的子问题。交叉思考可继续产生自己的子问题。
- 多路联系按实际数量自适应，不限定为二元或三元。多路来源显示为一个汇合节点及 N 路来源；不展开为 N×N 的两两联系。
- 全貌保留；密集时通过独立线口、焦点高亮、局部来源列表与缩放文字层级辅助辨认，不持续运行物理动画。
- EPUB 保留章节、原书页码（若文件提供）与 CFI 原文位置。阅读页码按实际版面计算，可输入全书页码跳转；窗口尺寸变化重新分页，笔记和同步进度仍以原文位置定位。
- 不改变个人资料内容，不自动重组思想，不加入 AI 生成逻辑。测试使用虚构数据。

## 平台策略

Windows 保留已通过试用的预算、托盘、稳定模型缓存、默认关闭可选 GPU 及小事务储存。Mac 使用相同后台计算、列表、绘制续作与小事务恢复，保留原模型与图形默认值，退出前增加检查点保护。Android 与 Web 使用已有原生分块／IndexedDB 储存，迁入界面调度、后台计算、共享识别与受限缓存；不能直接使用 Electron 的文件 worker。性能参数按平台调整，避免把 Windows 的图形策略直接套用到手机。

## 交接提示词

继续本计划时先读原工程状态与此表，保留 Windows 已确认的性能基线。先验证根问题折叠仅发生在选择器，多源交叉没有被改成单一父问题；测试跨页、祖先与后代共同关联及交叉的子问题。EPUB 不能把字符估算位置冒充实际阅读页，不能把阅读页码冒充纸书页码；数字跳转必须定位到 CFI，重排后仍能回到原文。以虚构资料检查各端，再构建和签名，所有文件核验完成后发布独立 v3.14-build330 Release。公开页面只写面向使用者的说明，Mac 下载第一且绿色。保留现有书籍、笔记、连接、签名和应用 ID，不在日志输出私钥或密码。

## 已完成的验证与边界

- 新增 `test-question-links-330.cjs`：两路至十一路关联、相同来源不同交叉的独立线口、完整路径、交叉子问题、原层级不可变，以及 EPUB 数字页码和缓存标识校验。
- `test-release330-ui.cjs`：以虚构 EPUB 与问题页检查主问题折叠、逐层展开、四路独立来源、图中四条聚焦线、多级目录、同文件小节、原书页码、数字跳页、窗口重新分页。Mac 分支另检查真实退出前保存最新未提交的阅读草稿。
- 在最终截图检查中发现 EPUB 重排页码与正文列宽不一致，已通过实际阅读容器的尺寸观察补齐正文 resize，并增加尺寸一致性断言；收起书架、打开笔记栏或拖动比较阅读分隔线也沿用这一处理。
- 进一步收紧重排验收：重排前的原文 CFI 必须仍位于重排后的可见起止 CFI 内。可见 EPUB 使用容器的明确尺寸，统一由尺寸观察驱动重排，避免与引擎自己的窗口重排并发；字体稳定后重新锚定同一段原文。此修复通过强化断言后纳入所有最终安装包。
- Mac PDF 分支覆盖原生文字、扫描识别、滚动与输入、换页取消、稳定缓存和搜索；各端共享逻辑仍保持平台原识别模型。恢复、小事务与原生后台保存检查 31 项通过；移动 API 检查包含超过 30 MB 的分块储存。
- 同步检查覆盖三设备、书籍传输、冲突、归档/清理、错误身份、离线恢复与新数据结构。所有云测试使用模拟数据与服务，不连接个人云端资料。
- Web 手机及平板宽度检查覆盖首次说明、选字过程笔记、章节与问题关联、EPUB、离线重开、草稿、模拟同步和多窗口并发保存。官网检查包括 Mac 第一绿色入口、三个宽度无横向溢出及首次安装步骤。
- Mac 原生进程已执行交互检查；Windows 应用分支在 Mac 模拟执行不等于 Windows 硬件性能实测。Windows 安装验收另由 GitHub Windows runner 执行。Android 构建、lint、原证书与包资源检查不等于全型号手机实测；Chrome 平板尺寸检查不等于 iOS Safari 实机验收。
- 桌面主项目、mobile、webapp 分别进行 TypeScript 检查。主项目排除独立 Web host 的模板与生成目录；该 host 使用部署脚本在独立暂存工程中构建，浏览器端继续单独检查。
