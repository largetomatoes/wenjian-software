# 问间 3.141（345）跨版本更新

用户允许跨版本更新，不要求逐次追随发行。本次以已验收 Mac 为基准更新 Windows、Android 与 iPhone/iPad Web App。保持资料位置、应用身份、原同步协议、Android 签名和 Web App 域名；不退出或替换当前使用中的正式 Mac。

## 发行身份

- 内部构建统一 345，显示 3.141（345）。
- 本次正式标签采用 `v3.141`，原因为 320 的实际检测器只认识纯版本标签；安装包仍为 `Wenjian-3.141-build345-平台` 标准名称，清单为 `update-manifest-345.json`。
- 标签、清单签名和下载路径对应同一个 Release；公钥继续沿用。后续发行可恢复 `v3.141-buildN`，345 已能识别。
- 319 写死旧 `mac-` 地址，无法靠修改新仓库源码远程修复。发布说明、官网和新版更新界面明确一次覆盖安装的办法；不承诺旧界面能收到新增提示。

## 功能与实现

- 桌面端启用后台 SQLite 记录事务：普通修改按变化记录保存，OCR 按页载入，输入先在编辑器中即时响应。
- 首次跨版迁移保留旧文件、日志与草稿，暂存迁移并完整核对后启用；已有 SQLite 不重新导入旧 JSON。
- 后续更新保护从当前数据库导出一致性资料和草稿，避免只备份陈旧 JSON。保留更新签名、SHA256、启动核对及失败恢复。若回退后的旧程序或外部工具改写旧资料文件，新版停止载入并保留两份资料，避免静默忽略后写的内容；正常启动只核对文件元数据，不再解析整个旧 JSON。
- 各端使用同一阅读编辑器、高亮配色与笔记板交互。手机继续原生分块保存，Web 继续 IndexedDB；不把桌面存储文件强行搬进手机。
- 修复 PDF/OCR/EPUB 摘录拖入笔记板正文上下空白处；保留引用定位与修改历史。
- 更新界面说明可跳跃升级，失败时提供手动覆盖入口；Mac 对 App Translocation 和不可写目录明确提示，不绕过 Gatekeeper。
- Windows 保留原字体、GPU 默认关闭、托盘、安装磁盘选择；可从已核验的同版本已发布 Electron 二进制离线重建，所有应用代码与资源重新生成。

## 验收与发布顺序

1. 类型检查、事务/恢复/备份/迁移/签名/旧检测器回归。
2. Mac 候选包实际输入、OCR、高亮、拖入、同步协议、安装与失败恢复。
3. Windows 实际安装、覆盖、字体、回滚；319/320/321/339/344 原包到新版安装与原资料迁移分别验收。
4. Android 原生构建与单元测试、原证书校验。手机尺寸 Chromium、iPhone/iPad WebKit 的交互测试与实体设备验收分别记录。
5. 完整源码和所有附件上传 Release 草稿；远端大小、SHA256 与签名逐项检查。
6. 所有平台附件齐备且检查通过后正式发布，再更新官网、两条静态发现索引和原 Web App。公开入口重新验证。

详细结果和边界在附件 validation-345.json 中记录；浏览器模拟不作为实体手机或 Windows 驱动性能测试。
